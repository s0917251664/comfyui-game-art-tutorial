# 平台 agent 內建生圖 vs 本專案固定流程（2026-10-19～20）

精簡紀錄。原始表格、腳本與證據圖在封存分支 `claude/project-thread-s1ejng`（PR #12）的 `docs/experiments/2026-10-19-windows-results.md`，平常不需要讀。

## 怎麼做的

- 主機：Windows 11、RTX 4080 16GB、ComfyUI 0.34.0。我方用固定 task／template（當時預設 SDXL）。
- 平台：Grok Build 1.0.46（`grok -p`，headless）與 codex-cli 0.163.0（`codex exec`，ChatGPT 登入）。兩邊都不回報底層模型名、沒有 seed、沒有遮罩參數；方案與用量沒有記錄。
- 素材：自行生成的騎士圖（10-19）；角色類實驗 10-20 再用 Skye 遊戲角色重跑一次（圖只留本機，這裡只有文字）。
- 實驗：E1 可重現、E2 換武器且範圍外不變、E3 角色一致（5 個姿勢）、E4 透明背景、E5 圖上文字、E6 小範圍改色、E7 影片與 3D、E8 時間。
- 限制：單一素材、每格一次或少量重複、我目視評分、非盲評；只代表當日版本。

## 結果

| 項目 | 我方 | Grok | Codex |
|---|---|---|---|
| 可重現 | 固定 seed 重跑 0% 像素差 | 無 seed，每次不同 | 無 seed，每次不同 |
| 換武器後範圍外不變 | 不貼回 79–99% 像素被改；`edit composite` 貼回後 **0** | 騎士版尺寸被改無法比；Skye 版同尺寸，範圍外仍有約 1–7% 變動，且新舊武器並存 | 尺寸被改，無法逐像素驗證 |
| 換武器的畫面品質 | 差（SDXL `guided_inpaint`：殘影、多長手臂，約 1–2/5） | 好 | 好 |
| 角色一致（5 姿勢） | `character_action` 最差（髮色眼色全變）；FLUX.2 編修外觀保住但武器被換或不跟手；Qwen 三參考最好但約 7 分鐘／張 | 外觀保住，被姿勢圖上的錘子帶偏；一張 429 限流 | 外觀保住；Skye 版 5/5 錘在手上 |
| 透明背景 | `icon_asset` 原生 RGBA | JPEG，沒有透明 | 原生 RGBA |
| 圖上文字（中英） | 0/25 | 24/25 | 15/15 |
| 單張耗時 | 約 7 秒（SDXL） | 約 24–43 秒 | 約 47–59 秒 |
| 成本 | 本機免費 | 方案額度 | 方案額度 |

搭配實測（10-20）：平台畫好的結果縮回原尺寸，再用我方同一張遮罩 `edit composite` 貼回原圖，四組範圍外都是 **0**。改色（領巾變紅）自然可用；換成比原物件長的武器時，遮罩外的部分會被切掉，所以**遮罩要涵蓋新物件的範圍**。

影片與 3D（E7）：`video/wan/img2video` 約 36 秒出 2 秒影片、`3d/hunyuan3d-2mv/multiview` 約 40 秒出無貼圖網格，都要加 `--allow-unverified-platform`，只算技術試驗。

順帶發現：

- ComfyUI 收到**完全相同**的請求會直接回傳快取、不重算（約 1 秒、檔名不變）。測可重現性時要穿插別的請求。
- `inpaint` 調低 denoise 會變灰：實測 1.0 正常，0.6／0.3 遮罩內變成灰色色塊（已寫進[修圖失敗診斷](../knowledge/art/edit-failure-diagnosis.md)）。

## 當時的結論

各有擅長：平台贏在畫面品質、文字、一致性；固定流程贏在可重現、可證明沒改的地方不變、速度與免費。建議搭配：平台或模型出圖，固定流程用遮罩貼回原圖。

## 結論複查（2026-11-05，對照 main cb86da4）

10-19 之後 main 多了 `pose-edit`（FLUX.2 改姿勢）、`image/flux2/edit` 在 windows-cuda 通過技術檢查、SAM3 追蹤 template、去背指南。逐條：

| 結論 | 狀態 | 現在的說法 |
|---|---|---|
| 固定 seed 可重現、平台不行 | **仍有效** | 同機、同版本才成立；不同 GPU 不保證逐位元相同 |
| 貼回後範圍外 0 像素，是固定流程最穩的優勢 | **仍有效** | 已是 Steve 的規則：任何編修都要把沒改的區域貼回原圖（見[編修 Demo 紀錄](2026-11-03-edit-demos.md)） |
| 我方改圖品質差（換武器 1–2/5） | **已更新** | 那是 SDXL `inpaint`／`guided_inpaint`。現在換材質、換顏色先走本機換色或 FLUX.2 `flux2_edit`＋貼回，品質明顯較好；SDXL 局部重繪在細長物件上仍只會塗灰，不建議 |
| 角色一致：`character_action` 最弱，Qwen 最好但慢 | **已更新** | 改姿勢現在用 `gameart.py pose-edit`（FLUX.2，約 28 秒／張），再把改動區以外貼回原圖；Qwen 三參考仍是 draft，只在 FLUX.2 做不到時才試 |
| 我方透明背景只有 `icon_asset` | **已更新** | 任何靜圖 task 都可加 `--remove-bg`（ComfyUI 內 BiRefNet），半透明特效改用亮度轉透明，見[去背指南](../knowledge/art/background-removal.md) |
| 我方不能出字（0/25） | **仍有效（限 SDXL）** | 文字仍建議後製加字或交給平台；FLUX.2 出字沒有測過，不推定 |
| 平台一律無法驗證範圍外 | **已作廢** | Skye 版 Grok 尺寸與輸入相同，可量；正確說法是「平台沒有遮罩保證，同尺寸時仍有變動，尺寸不同時無法驗證」 |
| 平台出圖、我方貼回可行 | **仍有效** | 遮罩要涵蓋新物件範圍 |
| 影片／3D 一條指令、技術試驗 | **仍有效** | 但 Wan 2.2 5B 做不出乾淨的揮砍動作（11-03 v10），動作片改試 `video/h3/img2video`（draft） |
| 耗時數字（7 秒、24–59 秒） | **仍有效（當日數字）** | 只是 SDXL 的數字；FLUX.2 編修約 28–32 秒 |
| ComfyUI 相同請求回傳快取 | **仍有效** | ComfyUI 本身的行為 |
| 機器快照過期需手動複製 device_config | **已作廢** | 當時的臨時狀況；照 AGENTS.md 用 `gameart.py doctor`／`doctor --refresh` |
| 實驗腳本 `run_*_experiments.py` | **不收進 main** | 一次性驅動腳本（其中一支寫死 Skye 本機路徑），不是可重用工具；留在封存分支 |

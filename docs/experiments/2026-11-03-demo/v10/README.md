# Demo v10：騎士揮砍影片＋追蹤整把劍換材質（保留 v1–v9）

## 1. 來源影片（圖生影片）
- 工具：`gameart.py run video/wan/img2video`（Wan 2.2 5B）試了 6 個候選（3 種提示詞 × seed 7、21、33、55、77、99；480×704、97 幀）：**都不是乾淨的揮砍**——有的幾乎不動（seed 21）、有的人物變形或鏡頭亂飛（seed 7、33、55、99）、seed 77 揮出但劍變細、人物漂移。Wan 這條路產生不出乾淨揮砍。
- 改用 `video/h3/img2video`（MiniMax H3，draft／未實測，加 `--allow-unverified-platform`）試了 2 個候選（seed 7 與 21，480×704、107 幀、約 100 秒／支）。
- 挑中：**seed 21**（`source.mp4`，107 幀、24fps、約 4.5 秒）。提示詞：騎士雙手把大劍從肩上舉過頭、斜向往下劈、再收回肩上，劍保持單一剛性直劍、鏡頭固定。理由：整段是「舉劍、下劈、收回肩上」，結束時回到起始姿勢；劍在整個動作中保持同一把完整的劍（沒有融化、複製或消失）、臉與盔甲穩定。seed 7 的劍最後換了位置和握法，沒有回到肩上。
- 限制：這是 draft 範本，下劈中段有模型自己加上的白色揮砍殘影與地面塵花；披風、姿勢與 A.png 有些不同（披風被風吹開）；劍刃邊緣有時略有鋸齒。

## 2. SAM3 追蹤（`video/sam3/track-text`，每次約 15 秒）
提示詞 `blue crystal`（劍刃）、`golden crossguard`（護手）、`hair`（頭髮前景）。
- 劍刃遮罩 107 幀都有，劈砍時刀尖朝下、橫向、舉起都有跟到（`mask_contact_sheet.jpg`：紅＝劍刃、黃＝護手）。
- 護手遮罩在第 50–91 幀中 39 幀（面積 0）追丟，這段是下劈到收劍的中段；本版護手不重新上色，沒有影響換色。
- 面積異常（與前後 9 幀中位數差 30% 以上）的幀：46、48、49、88、89、91。其中 46–49 是揮砍動態模糊的高速幀（劍變成一道藍色弧形光帶），遮罩涵蓋整條光帶；88–91 是劍橫向通過身前。逐幀目視：遮罩有跟到劍，沒有重新提示或補點。
- 我沒有對失敗幀做重新提示（re-prompt）或點提示；護手追丟的 39 幀是已知失敗，只是不影響這次換色。

## 3. 換材質（只改劍刃，不改形狀）
做法同 v6：依亮度對應到暗鋼→銀的色階（色階範圍固定取自第 0 幀）；劍遮罩 12 像素內（頭髮處 30 像素）的藍／青色像素中和；頭髮前景像素保持原樣；深藍劍鞘（色相、飽和度、亮度判斷）排除。
數字（`data/summary.json`、`data/per_frame.json`）：
- 劍附近（劍遮罩 30 像素內）藍／青色像素每幀平均 12,427 → **258**；最大 **732**（第 48 幀，動態模糊光帶）。
- 劍遮罩 30 像素以外，每幀相對來源變動 **0** 像素（107 幀最大 0）。

## 誠實限制
- 揮砍中段的白色藍色揮砍殘影（模型畫的特效光帶）沒有完全換色；遮罩涵蓋的部分變灰，沒被遮罩涵蓋的邊緣殘影仍帶淡藍（第 47–52 幀最明顯）。
- 第 60 幀附近劍與深色腿甲交界有少量深色雜點（遮罩略超出劍）。
- 動態模糊幀的灰色弧線只是原光帶換成灰色，不是清楚的劍形。
- 來源影片是單一次 draft 範本的生成結果，沒有逐幀人工修補。

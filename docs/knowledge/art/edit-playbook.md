# 修圖手冊：從一句話到對的操作

使用者說「把這裡改成…」「只換顏色」「這邊壞了」時，agent 常見的錯誤是整張重新生成再賭運氣。這頁把一句修圖需求拆成**要改什麼、要保留什麼**，再挑最小、最可控的操作。task 的選擇表見 [task 選擇](../art-generation.md)，情境的 brief 重點見 [編修情境](edit-scenarios.md)；這頁補的是**排序與停損**。旗標以 `generate.py <task> --help` 為準。

## 一、先分清楚三件事

動手前用一句話答完，答不出來就是還沒問清楚：

1. **改什麼**：哪個區域、哪個屬性（顏色、材質、形狀、內容有無、表情、姿勢、整體風格）。
2. **不能動什麼**：輪廓、角色身份、遮罩外所有像素、透明背景、構圖。
3. **改到什麼程度算完成**：由使用者驗收（[R1](../rules/candidate-review.md)），不由 agent 判定。

## 二、由低風險往高風險試（不要跳級）

| 順序 | 做法 | 適用 | 遮罩外會不會變 |
|---|---|---|---|
| 1 | 本機像素工具：`edit recolor`、`edit composite`、`vfx`、`design` | 純顏色、把已有的好版本拼回去、貼回道具、版面組裝 | 不會（逐 byte 保留，可驗證） |
| 2 | `inpaint`＋確認過的遮罩，之後用 `edit composite` 合回原圖 | 局部內容改寫、移除、修補崩壞 | 生成端會漂，合成後不會 |
| 3 | `guided_inpaint`（`pose`／`canny`／`depth` 鎖結構，可加 `--appearance-ref`） | 遮罩內結構不能變、外觀要換（換武器、換材質、換服裝） | 同上，一定要合成 |
| 4 | `refine`（整圖，調 `--denoise`） | 整體質感、草稿上色、同造型換風格 | 全圖都會動，沒有保證 |
| 5 | 重新生成（`concept`、`character_action`、`style_lock`…） | 前面都做不到，或使用者要的是新構圖 | 全部重來 |

原則：**能用上一級完成，就不要用下一級。** 純顏色用生成去賭是最典型的浪費（[單一物件換色](single-object-color.md) 的實測：`refine` 兩次都沒有命中目標顏色，本機 `recolor` 一次就成）。

## 三、常見修圖需求對照

| 使用者說 | 建議操作 | 一定要先有 | 常見失敗與對策 |
|---|---|---|---|
| 「把帽子換成紅色」 | `edit recolor`（色相旋轉）；材質也要變才用 `guided_inpaint` | 確認過的遮罩 | 邊緣殘色→遮罩收緊或調 `--hue-range`；低飽和色不會被轉 |
| 「把這個東西拿掉」 | `inpaint`，prompt 寫**遮罩內要出現的背景**（不是寫「移除 X」） | 遮罩要略大於物件（含陰影） | prompt 寫了被移除物的名字會把它畫回來 |
| 「這裡手／臉／配件壞了，修一下」 | 小範圍 `inpaint`，只蓋壞的那一塊，再 `composite` | 遮罩只蓋壞處 | 遮罩貪心→連好的地方一起重生；見 [遮罩](masking.md) |
| 「換武器／換服裝但姿勢要對」 | `guided_inpaint`＋`pose`（肢體）或 `canny`／`depth`（物件輪廓、起伏） | 遮罩、結構來源 | 純 `inpaint` 失敗率高，不要死磕；手指細節是已知上限 |
| 「材質換成皮革／金屬」 | `guided_inpaint`＋`--appearance-ref` 乾淨特寫 | 參考圖 | 抓的是印象不是圖案；不保證逐像素一致 |
| 「整體改成水彩／像這張的質感」 | `refine`（`--denoise` 0.4–0.6），或 `icon_asset` 外觀參考 | 風格參考 | 全圖會動；denoise 太低蓋不過原圖 |
| 「背景換掉、人物不動」 | 先用 `sam` 或手繪取得人物遮罩，`inpaint` 重繪背景（遮罩反選），再 `composite` | 人物遮罩 | 人物邊緣光暈→遮罩略微外擴再羽化；髮絲建議人工檢查 |
| 「加一個東西到畫面上」 | 在目標位置畫遮罩，`inpaint` 或 `guided_inpaint`，prompt 描述**該物件與周圍光線** | 遮罩位置與大小要先確認 | 遮罩太小畫不出形體；太大改動周邊 |
| 「放大／解析度不夠」 | `upscale`，沿用原 prompt | 定稿圖 | Mac 上大尺寸會失敗，見 [已知限制](known-limitations.md) |
| 「透明背景交付」 | `--remove-bg` 或 `icon_asset`，之後 `edit asset-audit` | — | Alpha 存在不等於去背品質，看白／黑／棋盤預覽 |
| 「擴圖（把畫面往外延伸）」 | **目前沒有固定 template**。如實告知；可提出實驗方案（見 [節點入門](comfyui-nodes-primer.md)） | — | 不拿 `inpaint` 勉強頂替後說完成 |
| 「改表情／換角度」 | 表情：臉部小遮罩 `inpaint`；換角度：`character_action` 或平面圖轉 3D 取角度（[平面圖轉 3D](image-to-3d.md)） | 角色參考 | 換角度不保證身份一致，要使用者逐張看 |

## 四、一輪修圖的標準流程

1. **釐清**：只補問前文沒有的資訊（改什麼／不能動什麼／有沒有參考圖）。
2. **取遮罩**：手繪（`mask-session`）或 SAM 候選（`sam`），看預覽，使用者確認；沿用已確認的範圍，不重問。格式陷阱（alpha=0 才是要改的區域）見 [遮罩](masking.md)。
3. **預檢**：`gameart.py run <id> --preflight` 或 `generate.py` 的能力檢查；缺能力在上傳前就停。
4. **一次只改一個變數**：固定 seed、來源、遮罩，只動 prompt 或 `--denoise` 或結構鎖強度其中一項。多項同時改就看不出誰有效。
5. **合回原圖**：`edit composite` 讓遮罩外逐 byte 不變；用 `edit compare` 看遮罩外有沒有變動。
6. **交使用者驗收**：給候選與差異圖，不自行 `review accept`。

## 五、停損規則

- **同一個需求同一條路最多 3 次**（每次必須改變一個明確的變數，不是單純換 seed）。3 次後仍不對，不要第 4 次；回到使用者，說明已試過什麼、推測原因（對照 [失敗診斷](edit-failure-diagnosis.md)），並提出換路線（升一級或降一級）或調整需求。
- **不靠換 seed 解結構性問題**：同位置重複出現的缺陷（例如 [已知限制](known-limitations.md) 中木框缺口）是模型傾向，不是運氣。
- **候選差距很小時不再抽**：改善幅度看不出來就停，不用抽樣來湊「看起來有改善」。
- **有界比較才用 `edit sweep`**：使用者明確要比較少數幾組參數時才用，最多 16 次；它不是盲目重抽工具。
- **每次嘗試都記錄**：prompt、seed、denoise、遮罩版本、來源版本、結果一句話。下一次失敗時才知道哪個變數已經試過（格式見 [result-records](../result-records.md)）。

## 六、prompt 寫法（局部重繪專用）

- **只描述遮罩內該出現的東西**，加上必要的周圍光線與材質脈絡（例如「腰間的棕色皮革刀鞘，與上衣同一側光源」）。不要把整張圖的描述再寫一遍。
- **寫要什麼，不寫不要什麼**：把不要的東西寫進正向 prompt 會被畫出來；不要的東西放 negative。
- **與參考圖衝突的文字會被蓋過**：參考圖是紅的、文字寫藍的，結果不穩定；改參考圖或改需求，不要靠加強語氣。
- **中文字、Logo、細小文字不要期待生成正確**：事後用 PIL 等工具疊加（[已知限制](known-limitations.md)）。

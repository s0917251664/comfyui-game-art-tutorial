# 圖片編修情境：判斷與界線

多參考圖、局部修改、保留角色或結構時，這頁說明每種情境該先講清楚什麼、通常走哪條路、哪些一定要人工確認。每個 task 實際吃哪些輸入，以 `generate.py <task> --help` 為準；共用的 brief 方法見 [brief 與驗收](brief-and-acceptance.md)。

參考圖板（`edit reference-board`）只協助人看素材與用途，不是生成輸入，也不會讓模型多吃參考圖。遮罩預覽只表達範圍意圖，不等於 Alpha 遮罩契約（見 [遮罩](masking.md)）。

| 情境 | brief 要講清楚 | 通常的路 | 必須人工確認／已知界線 |
|---|---|---|---|
| 角色一致性與換姿勢 | 哪張是角色來源；臉、髮型、服裝、裝備、比例哪些固定；哪張只提供姿勢；背景可否改 | `character_action`（角色加姿勢參考）。Q 版可能偵測不到骨架，`canny` 可能把衣服帽子輪廓一起帶入；沒有可用骨架不自動 fallback | 外觀和姿勢要分開看。姿勢參考的造型會污染結果，`asset-audit` 不認識角色特徵 |
| 換裝、配件、盔甲改版 | 要換什麼、要保留什麼；外觀參考只借造型、材質、配色的哪部分 | 有確認過的遮罩時走 `guided_inpaint` 的外觀參考；沿用使用者選定的角色版本做下一階段 | 輪廓、配件位置、身份是否保留；參考圖的模特、姿勢、背景有沒有被帶入 |
| 只改表面材質或顏色 | edit target；只改哪個表面、換成什麼；保留輪廓與鄰近部位 | 純顏色用本機 `recolor`；改紋理或材質才用生成（`guided_inpaint`），再用 `composite` 控制哪些像素回到原圖 | 生成可能超出遮罩語意邊界，遮罩外會漂移（要靠 `composite` 才能保證遮罩外不變）。材質命中不穩定，見 [單一物件換色](single-object-color.md) |
| 依風格參考改整體質感 | 來源與風格參考；只借筆觸、明暗、材質、色調的哪些 | `refine`（整圖），圖示用 `icon_asset` 的外觀參考 | `refine` 沒有遮罩，不能假設其他內容不變；外觀參考會帶入原圖不想要的東西 |
| 多張圖各有不同職責 | 每張標成來源、角色、姿勢、外觀、遮罩預覽、候選；衝突時的優先順序 | 依 task 各接既有欄位，傳原始圖而不是板面 | `flux2_edit` 只吃一張來源圖，不能當多參考 |
| 透明角色、道具、圖示交付 | 透明背景、完整輪廓、安全邊距；陰影、髮絲、半透明材料要不要 | `remove-bg` 或 `icon_asset`（永遠去背）；產後用 `asset-audit` | Alpha 通道存在不等於去背美術品質通過；要看白、黑、棋盤預覽有沒有光暈、洞、裁切 |
| 鎖定道具或圖示的結構 | 數量、輪廓、方向、色塊哪些不可變；改的是表面還是結構 | `icon_asset --structure-ref`（見 [結構範本](structure-ref.md)） | 數量與排列人工核對；結構鎖壓得住分區卻壓抑精細裝飾 |
| 分階段完成複合改動 | 把可分開驗收的部分排成階段（剪影、姿勢、服裝、表面材質），標明各階段的來源版本與不可變項 | 每階段各走對應 task，記錄 prompt、seed、輸入版本 | 不把未驗收的候選自動當母版；使用者要一次完成多項時照需求交付並逐項檢查 |
| 有界比較與回顧 | 固定來源、prompt、seed、參考，只列一兩個已支援參數 | `edit sweep`（最多 16 個候選）搭配 `compare`、`asset-audit` | 固定輸入不可掃描；像素差異不是語意判斷。技術結果、觀察、美術決定分開記錄 |

## 實跑觀察（2026-10-02，sdxl_standard，seed 20261002）

只代表這幾個案例，全部是待驗收候選：

- **局部材質（`guided_inpaint`）**：頭髮改成短絨，結果是密集細纖維、輪廓大致保留，但沒有精準呈現短絨。原始生成在遮罩外的保留區有九成以上像素有變動（926,576 中 870,763），按確認過的遮罩合成後保留區變動為 0。結論：遮罩外要保證不變一定要合成，不能靠生成。
- **角色姿勢（`character_action`）**：動作跟上了姿勢參考，但帽緣、捲髮、衣服形狀被姿勢參考污染，原角色身份沒有保住。換成 `pose` 後角色比較像，卻變成站姿且沒有槌子；姿勢偵測 `people=[]` 表示骨架沒偵測到，不能稱為成功的 pose 控制。task 狀態 `verified` 只表示輸出契約驗證過，不保證身份、姿勢或美術品質。
- **透明圖示（`icon_asset`）**：徽記區域 Alpha 全為 0，所以黑底預覽看不到；用 negative prompt 排除文字與徽記後輪廓也改變，單一修正不足以證明品質改善。

這三例展示 brief、task、本機工具如何串接，以及該如何記錄失配；不能據此宣稱 task 保證達成需求。

# 物件局部修正的取捨

本頁談物件的外觀、位置、角度與接合。角色姿勢、手與道具的關係屬於結構問題，先依下表選路，再照 [R5 生成方法停損](../rules/method-stop-loss.md)決定方法層級，不要一開始就局部重繪。

## 先選路

下表是目前有實跑紀錄的路線，都是小樣本或單一專案的觀察，輸出一律是待驗收候選。

| 需求 | 先走 | 界線 |
|---|---|---|
| 改單張角色的姿勢或手掌方向 | `gameart.py pose-edit`（底層 `image/flux2/edit`） | 一次一個大動作；不適合精準指定手指或武器握法。見[外部素材庫的可用結論](external-asset-libraries.md#可用結論先讀這裡) |
| 指定視角或姿勢，單圖編修保不住角色 | `image/flux2/edit-object-reference` 或其遮罩版，第二張放同一角色的參考 | Skye 背面與衝刺曾這樣做；參考欄位名稱是「物件」，用途要由提示詞說明，比例與配色仍要量 |
| 角色帶大型道具的動畫姿勢 | H3 `character-video-2`，給角色與武器參考，讓模型自己擺 | 見[持槌拖錘跑返工檢討](../experiences/armed-drag-run-rework-retro-2026-10.md)；道具外觀之後仍換回原圖 |
| 道具外觀不能跑掉 | 程式貼設計原圖，模型只畫人 | 見[橫向動作經驗](../experiences/side-scroller-character-anim-2026-10.md) |
| 定武器透視或替灰模上色 | 3D 定透視，再用 `image/flux2/edit-object-reference-masked` 照設計上色 | 見[圖轉 3D](image-to-3d.md)；角色用 3D 人偶或手模沒有成功過 |
| 雙手清楚握住短柄 | 目前沒有可靠路線 | 只靠文字描述幾乎都只畫一隻手，換大模型也沒解決。見[封面握錘失敗紀錄](../experiences/cover-hammer-grip-2026-10.md)；先估成本，必要時交給美術補 |

## 先分問題與固定點

局部修正先判斷「哪一種關係出了問題」，再決定修改範圍與方法。範圍不是越小越好：太窄可能沒有重建接合的空間，太大則會帶動原本正確的設計。

先區分外觀、位置／角度、接合、結構問題。將部件分成固定、可動與依附三類：例如接點偏移，可能只需轉動一段連接件，而不必移動整個物件或人物。保留一個穩定的握點與保留整雙手，是不同的限制；若可動部件必須帶動依附部件，應先說清楚取捨。

直接比較來源與候選的同一部位，比憑記憶判斷可靠。局部圖案定位可輔助確認移動方向，但像素匹配不會證明透視正確，也不會揭露當時採用的工具。

## 依問題選方法

層級照 [R5](../rules/method-stop-loss.md)；同一瑕疵連續兩輪沒解就換層級，並告訴使用者為什麼換。

| R5 層級 | 方法 | 適合評估的情況 | 需要付出的代價與檢查 |
|---|---|---|---|
| 1 調參數 | 文字指令編修 | 需求容易用語意描述，允許一定細節變化 | 模型可能以重設計代替位移；逐項檢查固定部件 |
| 2 確定性修補 | 幾何調整、程式貼原圖 | 道具外觀一律走這層；位置或角度可以估計，既有紋路值得保留 | 可能拉伸紋路、留下舊輪廓或破壞接合；幾何草稿與生成補縫分開記錄 |
| 3 局部重繪 | 遮罩局部重繪 | 問題範圍明確，需要重建內容 | 同一區域最多一次，不行就回乾淨來源；遮罩不提供正確幾何，仍可能改錯材質或手部；框到細長部件時可能連部件一起改掉 |
| 4 換條件重新生成 | 換參考圖組合或結構引導 | 手與道具的關係這類結構問題優先從這層開始 | 引導可能鎖住原錯誤；參考的來源與用途必須明確 |

需要保留區逐像素不變時，以使用者確認的遮罩合回原圖，並檢查保留區；不只靠提示詞承諾。遮罩與合成契約見[遮罩](masking.md)及[本機編修工具](edit-tools.md)。技術上的保留區零變動，不代表接縫、美術或結構驗收通過。

## 每輪的決策點

記錄來源版本、問題、固定與可動部件、選用方法及理由、輸入與輸出、實際失配、下一步。若是獨立比較，每輪從同一來源開始；若是補縫等分階段處理，則明確記錄中間草稿來源，不能混稱為同條件比較。

完成後分別檢查目標關係、保留區與交界。看到具體失配才調方法，不同時任意更換來源、模型和參數。

已完成的答案圖不能作為獨立解題的輸入；若使用它，該輪只能評估「有答案參考」的流程，須和獨立測試分開。對照圖可以說明部件關係，不能據此宣稱已復原歷史操作。

本頁不將任何候選自動標為接受，不更改 profile、驗證標籤或專案規則。案例見[錘子接合修正實驗](../experiences/hammer-joint-repair-2026-10.md)。

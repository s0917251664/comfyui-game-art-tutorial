# Skye 修圖對照實驗：平台用 Prompt（A／B 組）

本檔交給使用者貼到 ChatGPT 或 Grok。實驗規則檔 `protocol.md` 沒有收錄在 repo 中（本資料夾只有這份平台操作說明）；需要追溯規則全文時，向使用者索取原檔。

- 母圖：`output\experiments\skye-repair-20261007\source\skye_master.png`（1254×1254，SHA-256 `e0f9cb9c…acb89`，即 v9 報告的 APPROVED KEY VISUAL `pose-cover-final-v5.png`）。
- A 組只用自然語言；B 組可使用平台內建的局部編輯（例如 ChatGPT 的框選編輯）。兩組各開**新對話**，不要在同一個對話裡接著做。
- 每個平台各自一套 A／B。檔名中的組別字母固定為 `A` 或 `B`；不同平台放在不同子資料夾（見最後的操作說明）。

---

## 給使用者的操作說明

1. **開新對話**，上傳 `skye_master.png`，貼上下方「A 組 prompt」全文，送出。
2. 平台每產出一張圖就**立刻下載**，改成它指定的檔名（例如 `A_S2_r3.png`）。不要用截圖代替下載，不要再自行裁切或轉檔。
   - ChatGPT 下載鍵通常給 PNG；若只給 WebP／JPG，保留原副檔名，不要轉成 PNG（量測工具會記錄格式）。
3. 記錄每輪的大約耗時（從送出到出圖，分鐘，可以只估到 0.5 分）。平台無法計時，`minutes` 欄位由你補上。
4. 平台會自己決定要不要下一輪；你只需要回覆「繼續」。**不要替它補充修改方向**，否則 A 組就混入了人工指導。
   - 例外：平台跳過自檢、或沒有依規定檔名回報時，可以回覆一次「請照規則自檢並給出檔名」。這句話也記進 `notes`。
5. 每題開始前，如果平台似乎拿上一題的成品繼續改（D1 除外），重新上傳母圖並說「這一題從這張原圖開始」。
6. 全部完成後，平台會貼出 JSON。複製後存成 `logs\A_log.json`（UTF-8），把你記的 `minutes` 填進去，並把 `platform`、`model`、`date` 改成實際值（模型名稱看平台介面顯示的名稱；看不到就填 `"unknown"`）。
7. 文字報告存成 `logs\A_report.md`。
8. B 組：開另一個新對話，重複 1–7，用「B 組 prompt」，檔名與 log 改成 `B_…`。平台沒有局部編輯功能時，不跑 B 組，建立 `logs\B_log.json`，內容為 `{"schema_version": 1, "arm": "B", "platform": "<平台>", "status": "not_applicable", "reason": "平台無局部編輯功能"}`。
9. 兩個平台都跑時，資料夾如下（量測工具會依子資料夾分開處理）：

```
skye-repair-20261007\
  A\ChatGPT\A_S1_r1.png ...
  A\Grok\A_S1_r1.png ...
  B\ChatGPT\B_S1_r1.png ...
  logs\ChatGPT\A_log.json  A_report.md  B_log.json  B_report.md
  logs\Grok\A_log.json ...
```

只跑一個平台時，也請照這個結構放（`A\ChatGPT\…`），避免之後混淆。

10. 每題五輪、七題，最多 35 張。平台額度用完就停，在 `notes` 寫「額度用盡，停在 S? r?」，未做的題目 `status` 填 `"not_run"`。**不要換帳號或換模型接著跑**，那會變成另一組數據。

## A 組 prompt（只用自然語言）

> 以下整段複製貼上。

```
我在做一個修圖實驗，請你照下面規則執行，不要省略任何步驟。

【素材】
我上傳的圖是「母圖」。除了 D1 以外，每一題都要從這張母圖重新開始，不要拿上一題的成品接著改。

【規則】
1. 依序執行 S1、S2、S3、S4、S5、S6、D1 共 7 題。
2. 每題最多 5 輪。每一輪：
   a. 產出一張圖。
   b. 告訴我這張圖的檔名，格式為 A_<題號>_r<輪次>.png，例如 A_S2_r3.png。
   c. 自檢：拿成品和母圖比較，逐項列出問題，至少檢查「要求是否達成」「必須保留的部分有沒有被改」「形狀、比例、手、臉、配色有沒有走樣」「輸出尺寸」。
   d. 判斷這題是否完成。完成就換下一題；未完成就由你自己決定下一輪的修改文字，並把那句修改文字寫出來，再產出下一輪。
3. 只能用文字描述修改，不要要求我幫你圈選或塗抹範圍。
4. 第 5 輪仍未完成，就停止該題，記為 max_rounds；你判斷不可能修好而提前停止，記為 gave_up。
5. 每輪結束後等我回覆「繼續」再做下一輪。

【題目】（題目原文請照抄，不要改寫；你自己下一輪的修改文字另外寫）
S1：只把眼睛顏色改成紫色，其他完全不要變。
S2：把錘頭的冰晶改成熔岩材質，錘子形狀不變。
S3：在錘頭側面加一顆發光的符文寶石，其他不要變。
S4：修正握錘的手，讓手指自然地握住握把。
S5：在錘子周圍加上冰霧特效，角色本身不要變。
S6：同一個角色，改成雙手高舉錘子的姿勢。
D1：依序做 S1 → S2 → S3，每一步接續上一步的結果（第一步從母圖開始）。D1 的每一步各算一輪，檔名用 A_D1_r1.png（S1 步驟）、A_D1_r2.png（S2 步驟）、A_D1_r3.png（S3 步驟）；如某一步需要重做，接著用 r4、r5，並說明這一輪在重做哪一步。D1 總共最多 5 輪。

【最後輸出】
全部做完後，請輸出兩樣東西：

(1) 一段 JSON（無法輸出檔案就直接貼在對話裡，放在 ```json 區塊內），格式如下，欄位名稱不要改：
{"schema_version": 1, "arm": "A", "platform": "平台名稱", "model": "你所知道的模型名稱，不知道就填 unknown", "date": "YYYY-MM-DD",
 "cases": [{"id": "S1", "rounds": [{"round": 1, "file": "A_S1_r1.png", "instruction": "這一輪實際使用的修改文字",
   "self_check": "這一輪自檢發現的問題", "self_judged_done": false, "minutes": null}],
   "final_round": 1, "status": "done 或 gave_up 或 max_rounds", "notes": "其他說明"}]}
minutes 一律填 null，由我補。

(2) 一份文字報告：
- 每題結果：做了幾輪、最後是否達成、最後一張的檔名。
- 每題沒修好的部分，以及你認為修不好的原因（用你自己的說法）。
- 每一張輸出圖的實際尺寸（寬×高）；不知道就寫「不確定」。
```

### B 組框選時的人為約束（使用者自己遵守）

- 平台說框哪裡就框哪裡，不自行擴大或縮小；平台沒說範圍時，只框「題目提到的部位」。
- 不使用平台以外的工具修圖。
- 若平台的框選工具只能整張重畫（例如框選後仍改到框外），照實記在該輪 `notes`，不要重來。

## 共用 log schema

三組（A、B、C）相同；C 組由 agent 寫出。

```json
{"schema_version": 1, "arm": "A|B|C", "platform": "ChatGPT|Grok|ComfyUI", "model": "...", "date": "YYYY-MM-DD",
 "cases": [{"id": "S2", "rounds": [{"round": 1, "file": "A_S2_r1.png", "instruction": "實際使用的修改文字或參數",
   "self_check": "自檢發現", "self_judged_done": false, "minutes": 2.5}],
   "final_round": 3, "status": "done|gave_up|max_rounds", "notes": "..."}]}
```

允許的額外 `status`：`not_run`（額度用盡等原因未執行）、`not_applicable`（整組不適用，見 B 組說明）。

# 持槌拖錘跑返工檢討與決策流程（2026-10-19～22）

專案 `skye-ice-hammer-game`：在[橫向動作角色動畫](side-scroller-character-anim-2026-10.md)之後，補做「持槌時跑步」（側身跑、錘頭拖地），並統一全部動畫的比例與膚色。這支 20 格循環前後花了約 3 天、近 70 則使用者訊息，其中約 25 則是退件或糾正。這頁整理返工的原因，以及下次做「角色＋道具動作」時建議的決策順序，供 agent 與使用者預期管理。專案裡的決策與工具在該專案的 `DECISIONS.md` 與 `tools/`（本機檔案，另機未必存在）。

## 時間線（只列轉折）

| 日期 | 發生什麼 | 代價 |
|---|---|---|
| 10-19 | 原本已決定「移動不持槌」，使用者改成要拖錘跑；agent 用手工合成（貼手臂、拼上半身）做姿勢 | 一整天在「手臂黏在一起」「手臂畫在同一位置」「多一隻手」「握的手錯邊」之間來回 |
| 10-19 晚 | 使用者提議改用 H3 直接畫、多加限制 | 每輪仍有多手或空手幀 |
| 10-20 | 改走 VACE 局部重繪清多出的手；一度退回用一般跑步當底 | 使用者：「不是叫你重產嗎？」 |
| 10-21 上 | 修後腳與短褲接縫、手臂拉長超比例；交圖沒逐格放大看 | 使用者：「自檢技能是不是沒在用」 |
| 10-21 中 | 使用者提議「給角色參考圖和武器，讓模型自己擺姿勢」（H3 character-video-2） | **這條才真正解決姿勢問題** |
| 10-21 下 | 握的手判斷反覆（近側／遠側），最後接受近側版，但要求拳頭真的握住；之後顏色、比例、收槌時機、消失特效、跳躍收槌逐一被試玩抓出 | 每一項都是交付後才發現 |
| 10-22 | 量全部動畫才發現：持槌那群動畫本來就偏色，攻擊動畫中途角色縮小 6–16% | 早期就該有的檢查到最後才補 |

## 返工的原因

| 原因 | 證據（使用者原話節錄） | 本質 |
|---|---|---|
| 規格沒在生成前鎖定 | 「我以為你要用離鏡頭比較遠的那隻手」「其實手臂是不是有點拉到超比例」 | 握哪隻手、握點高度、手臂長度、錘子角度、循環長度，都是被退件時才定下來 |
| 手的判斷方法錯 | 「拿槌子的手反了」（兩次） | 用左右手標記判斷；角色左右對稱時無效。要用**遮擋**判斷：近側手臂畫在身體上面，遠側手被軀幹擋住 |
| 在錯的方法上硬撐 | 「你怎麼一直做一樣的錯」「動態修改也不一定要逐幀修改，我們不是有別的模型可以跑修正嗎？」 | 手工合成、接縫重繪連續失敗多輪仍繼續；有效的路（模型自己擺姿勢）是使用者提出的 |
| 在生成結果上層層補 | 短褲接縫用 FLUX 遮罩重繪兩次都失敗 | 已知的失敗做法（見[橫向動作經驗](side-scroller-character-anim-2026-10.md)「在已修過的圖上一層層補」）又重犯 |
| 自己沒驗就交 | 「認真看圖你覺得可以？」「低級的算圖錯誤」 | 沒逐格放大看就說可以；綠幕去背的綠邊在深色底一看就有，卻沒在深色底檢查 |
| 量錯指標 | 顏色「還是一樣啊」；切換時「角色比例會改變」 | 顏色只比平均值，差異被平均掉；比例用耳尖到腳的高度量，跑步姿勢彎腰前傾，量出來不準 |
| 基準不明 | 先把拖錘跑對齊持槌待機，事後發現持槌待機本身就和多數動畫不同色 | 沒有一開始指定「全部動畫以哪支為準」 |
| 遊戲內整合太晚 | 收槌太快、消失太硬、跳起錘子要消失 | 切換、計時、過渡只有進遊戲才看得到，卻放到最後 |
| 溝通成本 | 「我看不出差別」「你不需要我回覆吧，應該蠻明顯的？」「你應該回我中文」 | 給的比較圖看不出差異；可量化的事一直問使用者；語言規則沒守 |

## 最後真正有效的做法

- **讓模型自己擺姿勢**：H3 `character-video-2` 給角色參考圖＋武器參考圖＋簡短動作描述，模型自己決定手怎麼握。比手工合成身體部件、或在既有跑步上局部重繪都穩定；同一支影片內握的手不會換。
- **武器一律換成乾淨原圖**：量出畫面上拳頭的中心（距離轉換找最圓的深色塊），讓乾淨錘柄的直線穿過拳頭，錘頭角度解到剛好貼地；模型畫的金環、藍蓋殘渣清掉，被遮罩挖掉的皮膚從原片補回。
- **配色用調色盤逐色比**：去綠溢色後，按區域（皮膚、頭髮、深色布料、襯衫）把 Lab 平均移到基準動畫，每區設修正上限（第一次沒設上限把一支動畫的腿修成橘色）。
- **比例用頭部比對**：拿基準動畫的頭部當模板，逐格找最吻合的縮放倍率（含旋轉），只採信高分的格，以腳底為中心逐格縮放。
- **切換用專門的過渡**：身體直接換成對應動畫（比例已對齊），錘子用獨立圖層停在當格淡出，沿錘子軸線灑細冰晶顆粒；跳起、逾時都走同一個過渡。

## 下次的決策流程（角色＋道具動作）

照順序走；每一步的產出都要先過檢查，才進下一步或給使用者看。

1. **規格卡，一次確認**（生成前）：一頁寫清楚動作目的、握哪隻手（附遮擋示意圖，不寫左右）、握點位置、手臂長度規則、道具角度與接觸點、循環格數與 FPS、**比例與配色的基準動畫**、進出這個狀態的所有切換（逾時、跳躍、受傷、出招）、完成條件（哪些可量化、哪些要使用者判斷）。先查真人或其他遊戲的參考，再畫規劃圖給使用者確認；這一步曾經是唯一一次確認就過的做法。
2. **生成：先選最高層級的方法**：優先讓模型帶參考圖自己擺姿勢（`character-video-2`），同一批跑多個 seed；不要手工拼身體部件。
3. **停損**：同一個問題連續兩輪沒解，**換方法層級**（例如從合成換成重新生成、從局部重繪換成換參考圖），不是再調參數；也不回頭用已被否決的底圖。
4. **只做確定性修補**：道具換原圖、殘渣清理、去背都用程式；生成結果上的接縫重繪最多一次，不行就回到第 2 步。
5. **自動檢查，過了才給人看**：
   - 逐格放大的握柄特寫：手數、遮擋、拳頭是否包住握柄、多出的肢體。
   - 去背：深色底放大看綠邊、線稿是否偏綠、封閉區域不能透明。
   - 配色：和基準動畫的調色盤逐色並排，不只比平均值。
   - 比例：每格頭部對基準動畫的縮放倍率，同一支動畫內不能忽大忽小。
   - 循環接縫：首尾格差異。
6. **早進遊戲**：素材粗略可用就先放進遊戲，把第 1 步列的每一個切換都在遊戲裡截圖驗過，再做美術細修。
7. **交付**：先給結論與證據（並排比較圖要標出差異處），可量化的項目自己下結論；只把主觀美術取捨留給使用者，一次一個問題、附建議選項。

## 溝通約定

- 一律用繁體中文回覆。
- 比較圖要讓人一眼看出差別：同尺寸並排、標註差異位置；看不出差別的圖不要交。
- 可量化的事（比例、配色、握柄接觸、綠邊）自己量完直接報結果；主觀判斷（好不好看、要哪個版本）才問。
- 不說「最好」「可以了」，除非逐格檢查已過，並附檢查圖。
- 目標（goal）的完成條件要寫成可驗證的形式；「要等使用者說正確」這種條件會讓自動檢查反覆追問，增加雜訊。

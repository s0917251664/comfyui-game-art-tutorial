# 橫向動作角色動畫產線經驗（2026-10-15～18）

專案 `skye-ice-hammer-game`（Cocos Creator 3.8 H5、空洞騎士式橫向動作）：二頭身馬娘 Skye 拿大冰錘，做無武器移動、武器召喚／收回、三段輕擊與蓄力重擊。前後在 ComfyUI 跑了數百次生成。這頁記錄有效與失敗的做法，供之後做「角色＋大型道具」的遊戲動畫時預期管理；不是通用生成規則。

專案決策與逐幀驗收在該專案的 `DECISIONS.md`、`sprites/a34/FRAME_AUDIT.md`；中間產物在 `art-src/`。都是本機檔案，另機未必存在。

## 先定好再生成（每一項都曾因沒定而重做）

| 要先定的事 | 為什麼 |
|---|---|
| 角色基準圖與武器基準圖 | 使用者說「01 沒錯」被誤解成 candidate-01，整輪白做；有歧義先問 |
| 武器與角色的比例尺（本案：錘長 0.85 倍身高） | 生成後每幀量測，否則錘子大小每張不同 |
| 視角 | 先做純側面，使用者覺得沒美感改 3/4 側身，全部移動動畫重做 |
| 服裝是否左右對稱 | 朝左靠水平鏡像；口袋、臂章不對稱會換邊，最後改成兩邊都有 |
| Idle 錨點與持武器規則 | 武器平時收起、攻擊才變出（召喚即打擊）、閒置 3 秒或移動就收回；扛著大錘跑跳被判定不真實而取消 |
| 動作只要角色本身 | 特效（冰晶、弧光、衝擊波）另疊圖層；模型自帶的特效幀不能用 |

## 動作設計判斷（生成前先拆好）

美術生成之前，先把動作當遊戲設計拆解；這些判斷是試玩回饋與多輪退件後才定下來的。

| 判斷 | 本案結論與原因 |
|---|---|
| Idle 先定、所有動作以它為首尾 | 待機是正面微轉身（好看），移動才轉側面；攻擊、召喚、收回都從同一錨點出發回到同一錨點，換動作才不跳位 |
| 視角 | 純側面一度「沒美感」；3/4 側身臉較好看，但每支動作都要維持同角度，生成難度上升 |
| 有無武器分兩組 | 武器平時收起 → 移動只做無武器一組；扛大錘跑跳被判定不真實，改成移動就收回，省掉整組持槌移動 |
| 召喚即打擊 | 第一下就是攻擊，不能先召喚再揮；召喚只佔前搖的一半，命中瞬間一定看得到錘子 |
| 輕重差異不能只有快慢 | 只有「由上往下砸」很單調、沒打擊感；改成方向各異的連段：輕 1 橫掃 → 輕 2 上撈 → 輕 3 砸地，重擊＝按住蓄力、放開旋轉一圈砸地 |
| 張力來自預備與停頓 | 預備（往後拉、舉高）要夠大，命中幀壓扁、短暫停住再回彈；亂甩錘子不等於有張力。可先參考其他遊戲的同類招式拆關鍵姿勢 |
| 動畫只做動作、特效另疊 | 弧光、冰晶、衝擊波另做圖層，動畫幀裡不能有；模型自帶的拖尾要清掉 |
| 影格資料與畫面對齊 | 每招定 startup／active／recovery，動畫標 impactFrame，遊戲逐幀調速讓命中幀落在判定開始；打擊回饋（頓幀、輕震）先用程式做 |
| 出招不位移 | 還沒設計位移技前，所有攻擊原地出招（地面出招水平速度歸零，跑進攻擊也不滑步）；位移攻擊另做技能 |

## 有效的做法

| 做法 | 說明 |
|---|---|
| **錘子永遠貼設計原圖**，不讓模型重畫 | 模型會改粗細、柄尾、花紋。用程式把乾淨正面錘子沿握柄線旋轉縮放貼上，模型只負責手與身體 |
| **道具角度跟著揮擊平面換** | 每幀都貼同一張正面圖，橫掃看起來像在畫面裡平移（使用者指出）。從四視圖做角度庫（正面、3/4、鏡像 3/4、端面），畫面平面內揮（上撈、砸）用正面；水平揮伸直時看到錘頭端面，轉折處用 3/4。只換錘頭，握柄與手不動 |
| 設計圖先清掉中心虛線 | 四視圖原圖有灰色虛線（約第 257–258 欄）會一路帶進所有幀；做一張乾淨版 `weapon-front-clean.png` 再用 |
| **粗紅棍代替武器定姿勢** | 先讓模型畫「雙手握一根拳頭粗的紅色圓棍」，程式偵測紅棍的線，再沿同一線貼真錘子。棍子要和握柄一樣粗，細棍會讓拳頭包不住真握柄 |
| 錘頭放在身體後面、手疊回最上層 | 扛肩、往後揮時才不會蓋住臉與手 |
| 握柄交界小範圍遮罩重繪 | `edit-object-reference-masked` 只框手（或下巴交界）；細部區域放大 4～6 倍再重繪可去掉馬賽克 |
| Q 版大手握粗柄用「半握」 | 單手抓籃球式：手掌托住、手指半包，比完全握住自然 |
| H3 `transition` 給起點／終點，讓模型補動作過程 | 揮擊弧線比自己畫關鍵姿勢自然；關鍵姿勢自己合成時常被批「亂丟錘子、沒張力」 |
| **SAM3 追蹤 `girl`＋`mallet` 當遮罩清特效** | 遮罩外全部清掉；比用顏色判斷安全（顏色法會把頭髮、襯衫一起挖掉） |
| 綠幕去背後補實內部 | chroma key 會把深藍短褲、暗部吃成半透明；輪廓內補實、真正的綠色空隙保留透明；最後再補 ≤40px 針孔 |
| 腳底線與身高用錨點統一 | 所有幀放同一張 768² 畫布、同一腳底線；模型擺姿勢時會拉長腿，用「皮帶到腳底」距離壓回 |
| 揮擊特效跟著動畫裡的道具走 | 程式照判定時間畫固定弧線，會和動畫對不上（動畫在前搖就揮完）。每格記道具前端位置（SAM3 道具遮罩量測）寫進 anim.json，特效沿實際位置畫拖尾 |
| 冰雪特效：FLUX 黑底靜幀＋H3 動畫＋亮度透明 | 靜幀品質穩定；H3 img2video 從靜幀播到消散、transition 從黑畫面長出（冰刺）都好用。閃光鋪滿畫面的幀透明後會變方塊，要剔除。環形或簡單的特效（蓄力光環、小命中）用程式旋轉／縮放淡出比影片穩，循環也無接縫 |
| 空中招式影片要對齊腳底 | 影片裡角色自己會往下移，引擎又讓角色下墜，會墜兩次；逐格把腳底對齊同一條線，位移交給引擎 |
| 模型畫的錘子太大時，用遮罩核心找錘頭 | 錘頭蓋住握柄時，靠握柄顏色判斷錘頭方向會反；把 SAM3 錘子遮罩侵蝕掉細柄、取剩下的中心當錘頭較準，必要時逐格指定錘頭在左或右 |
| impactFrame 寫進 anim.json | 遊戲依招式影格數調速，讓命中幀剛好落在判定開始；召喚只佔前搖一半，命中瞬間一定看得到錘子 |

## 失敗的做法

| 做法 | 結果 |
|---|---|
| 讓模型連錘子一起重畫（全圖或大遮罩） | 錘頭破圖、透視斷開、柄插臉 |
| 用 Hunyuan3D 從四視圖重建的錘子 | 側面深度與頂部透視本身就不一致，建進模型後換面就壞 |
| 在已修過的圖上一層層補 | 交界越補越糊；回到乾淨底圖重來 |
| 單靠刪幀修瑕疵 | 動作變快、變跳；應從關鍵姿勢重新生成 |
| `transition` 提示「小跳」 | 模型照樣跳到出框；只能用頂點前後沒被切的幀 |
| 用顏色自動判斷「手有沒有握柄」 | 手套與錘身同為深藍，斷柄與完整柄判不出；改用 SAM3 `hand`／`mallet` 接觸量，已用修補前的斷柄幀驗證能抓出柄尾外露 |

## 環境與工具坑

- ComfyUI 每次上傳圖片後節點 input schema 指紋會變，影片 task 會拒跑；每支影片前先 `gameart.py doctor --refresh`。
- `transition` 不接受 `--negative`。
- 內建瀏覽器窗格隱藏時 rAF 暫停、Cocos 拿到 0 尺寸；測試頁注入 rAF→setTimeout 替身再用 `cc.director.tick` 逐幀驅動（只在瀏覽器測試內，不改遊戲檔）。
- Cocos 3.8 命令列建置成功的結束碼是 36；重建前只停占用 8765 的伺服器行程，不要殺全部 node。

## 帶走的判斷

- 角色＋大型道具的動畫，**道具一律程式貼原圖、模型只畫人**；這是讓設計不跑掉的關鍵。
- 動作張力靠影片模型（起點／終點）比靠手擺關鍵姿勢可靠；但中間幀的道具仍要逐幀檢查、必要時換成原圖。
- 驗收要逐幀、原尺寸、對照遊戲內實際檔案；縮圖總表會漏掉斷柄、針孔與殘點。
- 「兩隻手都在柄上」目前沒有可靠的機器判定（兩手常疊成一塊），最後一關仍需人眼。

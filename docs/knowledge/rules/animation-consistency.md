# R4 新動畫進遊戲前，配色與比例要對基準動畫量測通過

同一角色的每支動畫，角色的顏色與大小都要和專案指定的**基準動畫**一致；切換動作時角色不能變色、變大變小。新動畫（或重新生成、修改過的動畫）放進遊戲前要先量測，不靠交付後由使用者試玩抓出。

## 規則

1. **先指定基準動畫**：專案開始做動作組時，就指定一支動畫當配色與比例的基準（通常是 [R3](idle-anchoring.md) 的 Idle），寫進專案決策紀錄。之後所有動畫都對它比，不對「上一支做好的動畫」比，避免偏差一路傳下去。
2. **量配色**：按區域（皮膚、頭髮、深色布料、淺色衣服等）比較 Lab 平均，並把兩支動畫的調色盤（k-means 色塊）同尺寸並排看。**不能只比全圖平均**：區域的差異會被平均掉。道具、線稿、眼睛不列入。
3. **量比例**：以基準動畫的頭部當模板，逐格找最吻合的縮放倍率；**同一支動畫內也要逐格看**，不能只量第一格。只採信比對分數夠高的格。不用「耳尖到腳的高度」當比例：彎腰、跑跳時量出來不準。
4. **量去背**：綠幕或色鍵去背的素材，在深色底放大檢查邊緣有沒有綠邊、線稿有沒有偏綠；封閉區域不能變透明。
5. **切換要在遊戲裡看**：這支動畫和前後動畫之間的所有切換（逾時、跳躍、受傷、出招、收放武器），都要在遊戲裡截圖確認比例與位置連續。
6. **超過提醒門檻要修，修完再量一次**：
   - 比例：可信的格縮放倍率超出 1 ± 0.03。
   - 配色：任一區域 Lab 平均差（8-bit Lab）超過約 6。
   - 門檻只用來找要處理的地方，不能自動判定美術接受（[R1](candidate-review.md)）。修色要設每區修正上限，修完要放大看是否修壞（曾因沒設上限把腿修成橘色）。
7. 修正保留原檔備份與量測紀錄；量測結果和修正量寫進專案決策紀錄。

## 證據

2026-10-22 `skye-ice-hammer-game`：持槌拖錘跑交付後才被指出顏色不一致、切換時角色變大；補量全部動畫才發現持槌那群動畫一直偏色，攻擊動畫中途角色縮小 6–16%。過程、量測方式與修正做法見[持槌拖錘跑返工檢討](../experiences/armed-drag-run-rework-retro-2026-10.md)。該專案的量測工具在專案自己的 `tools/`（`anim_consistency.py`、`anim_scale_rot.py`、`anim_recolor.py`、`anim_rescale.py`），還沒做成本 repo 的通用工具。

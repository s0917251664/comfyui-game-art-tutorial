# 影片產線：設計判斷

為什麼影片這樣切、哪些決定已經拍板、哪些限制要先告訴使用者。task 的用法查 `generate.py <task> --help`，backend 與契約見 [README](README.md)，對照見 [cli](cli.md)。2026-08-26 的完整初稿（含模型 bake-off 逐項數據與分階段落地）保留在 [archive](../archive/video/design-2026-08-26.md)，平常不讀。

## 定位

ComfyUI 在這條產線是「虛擬攝影組加 VFX 元素組」，不是剪接台、導演或調色房。一次產出的單位是 **2–6 秒的鏡頭**或**可循環的特效元素**；更長的是把多支鏡頭組起來，不是讓模型一次吐出整部片。對外契約是 **task 名加 `--backend`**，不是模型名；模型檔、節點、私有 prompt tag 只活在 backend 實作裡。

## 為什麼影片不是「會動的 concept」

- 模型家族不同（Wan 2.2、MiniMax H3），和 SDXL 的 ControlNet／IPAdapter **完全不相容**，不能把 SDXL 節點接上影片 graph。
- 失敗模式多了時間軸問題：臉越變越不像、動作不閉環、前後鏡連戲斷。
- 時長是結構性上限，「長片」就是多鏡頭加外部組裝。
- 影片沒有等同 `--remove-bg` 的去背；透明輸出走 `gameart.py vfx` 後處理，不是模型原生 RGBA。

## 產線原則

- 先有靜幀，再有鏡頭：能用圖片產線定下來的角色、場景、道具，不要改用文生影片賭第一幀。
- 一次一支鏡頭：使用者說「做一部片子」時先出鏡頭表、逐鏡生成（[劇情流程](production-flow.md)），不收成一個超長 prompt。
- 完整成片組裝在 ComfyUI 外面：`video_concat` 只做基本順序串接；字幕、配樂、混音、完整時間線、傳統硬切與疊化交給剪接軟體。
- 風格（`--style`）活在圖片階段：影片模型吃已經長對的圖，不要指望影片 prompt 再切一次風格。
- 後端不由程式碼隱含選擇：每台機器的能力設定檔明確寫 `default_backend`，否則 CLI 要求 `--backend`。缺模型、runtime 或 node 時在上傳前直接報錯，不換 task、不靜默 fallback。
- 固定 graph 一律是 template（[R2](../rules/fixed-graphs.md)），新增走[擴充協議](../maintenance/extension-protocol.md)。

## 三個需求方向

1. **單純動畫特效（最該先做）**：題材單純、鏡頭鎖定、失敗成本低。從已定稿的靜幀出發，運動寫「原地循環、鏡頭鎖定」不寫情節；要進引擎就抽幀。要透明的不承諾逐幀 AI 去背，走綠幕加 unmix 或黑底亮度去背。
2. **有劇情的長片**：不是生成問題，是製片問題。60 秒 24 fps 約 1440 幀，本機一次數十幀，所以至少十幾個鏡頭，每鏡都要過連戲。不承諾「一個 prompt 出完整劇情片」「角色全程不崩」「自動對口型」「自動配樂」。
3. **動態轉場**：已知 A、B 畫面，模型只生中間那段，是首尾幀的本命題。三種不要混：硬切／疊化／擦除交剪接軟體；內容轉場（A 變成 B、場景溶解）才是 `transition`；遊戲 UI 或關卡切換也走 `transition`，結構要穩就先用結構範本鎖定靜幀。

沒點名但做片子缺了就卡死的能力：從靜幀做 I2V、鏡頭延續（`clip_extend`）、運鏡（`camera_move`，比讓角色自己演穩）、表演驅動（`pose_drive`）、Animatic（低解析短時長排時間）、環境循環 plate、insert／cutaway、抽幀交引擎。

## 模型選擇的理由

- **Wan 2.2 TI2V 5B**：公開權重、Apache 2.0、原生 workflow、16 GB 很鬆；較快但**無聲**，保原圖弱、身份較易漂。
- **MiniMax H3**：2026-08-26 在 RTX 4080 對打保原圖明顯較好（帽子、項鍊、法杖、臉認得出）、有立體聲 AAC，但較慢；歷史偏好 H3，現行由能力設定檔明確選。社群授權有品牌標示義務，商用前使用者自己讀條款。
- **Wan 14B**：不當預設，官方路徑 VRAM 遠超 16 GB，社群量化是易碎路徑；`transition` 畫質不夠時才當選用升級並走審視核准。
- **Wan 2.5 以後**：沒有公開權重，只有商業 API（Partner Node），素材要離機且計費；不符合「目前沒預算、只用本機免費模型」。有預算時預留「同一 task 名稱、換 backend」的位置，不重建產線。**LTX 2.5** 是另一個本機模型，名字別和 Wan 2.5 混；權重 gated，本輪不測。
- 迭代原則同圖片換底模：走審視核准，不為追版本號改產線。

## 已拍板的決定（2026-08-26）

1. 四種成品都要：特效循環、靜幀 I2V、內容轉場、有分鏡的短過場，不因「先做最小可用」拿掉任何一種。
2. 交付 mp4 plate 與 sprite frames 兩種：所有 task 都留影片檔，`fx_loop` 預設抽幀，`img2video` 與其他 task 要明確要求才抽。
3. 「有劇情的長片」是近期要交的產品，鏡頭表從第一天就是一等公民。
4. 不在文件鎖死步數、CFG、精確幀數、精確解析度；不設計 ComfyUI 內建時間線；不把完整時間線塞進 `video_concat`。

## 要先告訴使用者的限制

- 一次數秒，不是數分鐘。
- 身份會漂：同一角色連續多鏡，I2V 比靜態 IPAdapter 更容易越走越不像。緩解：永遠從定稿靜幀出發、鏡不要太長、下一鏡吃上一鏡尾幀；新鏡頭首幀可變時走 `character_video`。
- Loop 不是預設能力：`img2video` 不保證能 loop；`fx_loop` 才驗循環。
- 文字、Logo、UI 字更弱；聲音依 backend（Wan 無聲、H3 有 AAC）；`video_concat` 混合有聲無聲預設拒絕。
- 5B 畫質是草稿到中段可用，不是院線；交件級要走選用升級或雲端 API，是明確的升級決策。
- 乾淨 clone 不附影片模型與本機設定；一台機器的實測不能代表另一台。

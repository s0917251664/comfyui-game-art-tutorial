# 劇情影片製作流程：判斷與界線

把故事、長影片或多鏡過場拆成節拍、分鏡、連續性紀錄、逐鏡製作與驗收。本頁只寫判斷；每個 task 的旗標查 `generate.py <task> --help`，音訊與對嘴工具查 `gameart.py film-audio|film-qwen|film-lipsync --help`。單支「讓靜幀動起來」直接用影片 task（[影片知識](README.md)）；同一角色的一組遊戲動作走 [動作組](../animation/workflow.md)。

## 基本事實

- 現有影片單鏡 2–6 秒、固定 24 FPS、生成長邊至多 768。長影片是分鏡、逐支生成、剪接的製作流程，沒有一鍵長片，也沒有任意精確時長的保證。
- 使用者只要規劃就完成分鏡為止，不自動生成。缺生成能力時照樣交付規劃，列出哪些鏡頭被擋住。
- 字幕燒錄、ducking、time stretch、複雜轉場、完整時間線留給外部剪接工具。

## 製作順序

1. **台詞與聲音時序**：有台詞時先整理台詞 ID、聲線、版本、停頓，用本機 TTS 產候選音檔，聽過並記下實測秒數。TTS 技術通過不代表台詞、表演、聲線被接受；改台詞或聲音後更新版本與時間。
2. **劇情節拍**：每段寫起因、動作、結果，以及觀眾該看懂什麼，再決定幾個鏡頭。長作品按場景分批。
3. **連續性紀錄**：固定角色身份參考、服裝、物件持有者、場景位置、光線、左右方向，並記事件前後的改變。角色參考圖與 seed 是輔助，不保證身份或互動正確。
4. **粗分鏡**：依台詞實測長度安排說話鏡頭與停頓；先用文字、簡單構圖或使用者草圖定站位、景別、動作方向、剪接點。文字表不能稱為視覺分鏡。
5. **節奏預視（Animatic）**：核對鏡頭順序、台詞秒數、停頓與總長；有靜幀與音訊時用 `film-audio animatic` 出有聲預視。沒有素材就標示沒有預視，不把紙上檢查稱為 Animatic。
6. **代表鏡頭試作**：先做最容易暴露身份、多人互動、持物者、接觸動作問題的一鏡；起始靜幀先經使用者決定，錯誤靜幀不能流進影片。
7. **逐鏡生成**：通過代表鏡頭後分批做其餘鏡頭；每鏡 prompt 只寫該鏡的主事件、起始狀態、動作與結束狀態，不把整篇劇本塞進一鏡。
8. **串接與驗收**：明確設定順序、尺寸與音訊政策後用 `video_concat` 串接已接受的版本；最後檢查全片是否看懂、節奏、實際時長與聲音。

使用者還沒接受必要素材時，繼續做不依賴它的規劃，把依賴步驟標為待確認。

## 鏡頭對應的 task

| 鏡頭目的 | task |
|---|---|
| 已定構圖中角色或環境動起來 | `img2video` |
| 主體靜止、只推拉搖鏡 | `camera_move` |
| 參考角色演新鏡頭，首幀可改 | `character_video` |
| 已有姿勢草圖，先做角色起始畫面 | 圖片 `character_action`，驗收後再走影片 |
| 有動作參考影片 | `pose_drive` |
| 同場動作接續 | `clip_extend`（不是不同場景的普通切鏡） |
| A 狀態逐步變成 B | `transition`（不是硬切或疊化） |
| 依序接片 | `video_concat` |

task 是否可用依當次能力快照。多人接觸難以可靠呈現時，可建議拆成「準備、接觸特寫、反應、結果」，但不能偷偷改掉使用者要的事件。模型把敵人的物件畫到主角手上屬於內容失敗，不能因 prompt 有寫就判成功。

## 驗收與失敗

逐鏡先看主體、誰持物、動作方向、接觸位置、事件結果，再看角色、手部與裝備變形、背景、鏡頭。相鄰鏡頭查左右方向、視線、持物手、衣裝損傷、光線與起訖狀態；刻意跨軸或跳接要記敘事理由。

失敗先分類：構圖、身份、動作或持物、時間連續性、技術契約。只重做受影響的鏡頭；來源或起訖改變時，標記依賴它的鏡頭與舊合成待重驗，新版本不繼承舊版的接受狀態。沒有有效控制手段就標為受限，不盲目重送。狀態用 `planned`、`blocked`、`candidate`、`accepted`、`rejected`，技術狀態另記。

## 本機配音與對嘴（不經 ComfyUI）

`film-audio`、`film-qwen`、`film-lipsync` 是本機 Python 工具，不是 template：

- **TTS**：SAPI 與 Piper 先當聲線草稿與台詞量時；Qwen3 中文聲線較佳但仍要聽過。三個引擎都要明確指定，不自動下載模型或換聲線。已測的 Qwen 台詞 6.72 秒，長於 2–6 秒的單鏡，不能直接當一個生成鏡頭：要當跨剪接的旁白，或依語意拆句、分到多鏡，混音時按時間線放置。
- **混音與預視**：只提供疊混、Animatic、把一條音訊配到既有 24 FPS 影片；不做字幕、ducking、time stretch、配樂生成。配音長短不符，調整計畫，或明確選擇補靜音／裁切。
- **對嘴**：MuseTalk 適合單一、近正面的清晰臉部特寫；多臉、側臉、遮擋、小臉不保證可用。它不會替靜止來源補出身體表演，要先用 `img2video` 之類做出呼吸、眨眼、視線的候選，臉部穩定後才做嘴型。來源影片必須涵蓋整句台詞，工具不循環、裁切或改速。技術契約通過，但嘴型自然度、特定角色的適用性尚未驗收；接嘴型後仍要重驗臉部貼合與整體自然度。
- 實測只驗證了時間線、編碼與配音的技術契約，用的是未接受的素材與測試聲音，不能當成真實分鏡作品或劇情成片。

## 研究參考與取捨

分鏡與長片方法參考過 OpenMontage（階段區分）、Storyboarder（快速粗分鏡與時間預視）；SkyReels-V2 與 LongLive 只是長影片生成的研究對照，沒有採用其模型或執行器，也不能從示範推定本機能力。代表鏡頭先行、技術契約、人工內容接受、固定 task 與重做邊界是本專案自己的決定。本流程尚未完成端到端的多鏡作品驗收。

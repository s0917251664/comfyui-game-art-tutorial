# Wan Animate 與 SCAIL-2：怎麼選、已知取捨

兩者都是「用來源影片的動作驅動參考角色」的 template 路線，用 `gameart.py run video/wan-animate/<id>` 執行（沒有 `generate.py` task，不由 H3／Wan 5B 的 `video_capabilities.json` 判定）。可用的 template、slot、option、模型 pin 與平台狀態以 `gameart.py run show <id>` 為準；執行前一律先 `--preflight`。安裝 pin 與歷史安裝測試見 [安裝紀錄](wan-animate-install.md)，受控學習方式見 [評估筆記](animation-evaluation.md)。

## 怎麼選

| 需求 | 選擇 |
|---|---|
| 把參考角色放進來源影片（保留來源背景） | Wan Animate **Mix**，或 SCAIL-2 替換模式 |
| 來源動作驅動參考角色（背景由參考圖決定） | Wan Animate **Move**，或 SCAIL-2 動畫模式 |
| 片長 ≤ 33 幀 | 單段 template |
| 約 3.8 秒（61 幀） | 兩段延伸 template（只有兩段；更長沒有 template，停止並告知，不臨場複製節點。真要新的固定 graph 走 [擴充協議](../maintenance/extension-protocol.md)） |
| 多角色，或要依顏色綁定身份 | SCAIL-2 |
| 身份一致性優先 | SCAIL-2 比 Wan Animate 穩 |

兩個模型不能互相推定能力或品質；一方結果不佳時不自動改跑另一方，由使用者決定。

## Wan Animate 的取捨

- 輸入是 16 FPS CFR 的有界片段，先用既有媒體工具切好；解析度只實測過 384×384 與直式 384×640，其他尺寸視為未實測（先跑 17 幀看顯存），16 GB 卡的較大尺寸可能 OOM，失敗時保留證據、不自動降尺寸重送。
- Mix 的點位座標是輸出寬高中心裁切後的座標，要依本次來源的人物確認，不能沿用別支影片的點位；Move 不給點位，背景由參考圖與 brief 定義。
- prompt 描述實際觀察到的動作與身份錨點，不加入來源沒有的動作或道具。安裝期測試把「在房間跳舞」當 prompt、來源卻是頭手近景，疑似讓動作與身份互相牽扯，但沒有對照實驗證實，不可寫成已證實原因。
- 品質：身份會漂移（機器人相機頭變粉紅人形頭）、Move 曾憑空出現吉他、肩膀手臂手部有變形；Move61 沒有再出現幻覺吉他，但手指手掌仍變形。延伸段第 32→33 幀的接縫要人工看。不可宣稱 prompt 已解決身份漂移。
- 預設不輸出音訊；要保留來源音訊用 `keep_audio` option。實測的音訊是合成測試音，不代表真實對白的嘴型同步。三段以上、多角色未測。

## SCAIL-2 的取捨

- 用來源影片本身當 pose 輸入，再用 SAM3 依文字追蹤人物，產生彩色身份遮罩把參考圖角色與影片人物一一綁定。遮罩由模型節點依模式處理，不要自己準備黑白二值遮罩。
- **參考圖構圖主導輸出比例**：參考圖是大頭照時，遠景或背影來源會被畫成大頭特寫；把參考圖縮小、擺在來源人物頭部的位置與大小（同輸出寬高的灰底畫布）後，遠景鏡頭恢復全身構圖。近景來源配近景參考圖本來就跟得上。兩種模式都傾向輸出全身構圖，要貼合來源鏡頭的工作先用相同取景的參考圖測試。
- **SAM3 文字要具體**：太籠統會把非主角也追蹤進去，替換後旁邊的角色會消失、畫面被重畫（`man` 要改 `man with black hair`）。送出前可先用 SAM3 template 用同一個詞看遮罩，見 [SAM3 追蹤](sam3-tracking.md)。多人時文字寫具體，或用 `object_indices` 篩人；追蹤失敗時輸出仍會產生但動作不會跟隨，所以抽幀要確認動作對應。多角色時顏色依第一次出現的位置由左到右分配，參考圖與來源影片的人物順序要一致。
- **整畫面重畫**：道具與特效會被重畫而不是保留原片（變身腰帶變成一般皮帶、鎧甲細節變少）。需要原片道具完全不變時，SCAIL-2 不適合；改走局部重繪（VACE）。
- 主模型用 FP8 scaled（官方範本的 FP16 約 32.8 GB 不適合 16 GB 顯卡）；16 GB 可跑 384×384、33 幀分段，另在 832×448 試過 33 與 61 幀（顯存尖峰約 15 GB，含其他程式）。未測：官方 81 幀段長、三段以上、多角色、音訊、不用蒸餾 LoRA 的品質模式。

## 一律是 candidate

技術檢查通過只代表輸出契約通過。逐項看 `keyframes/` 與影片（身份錨點、肢體與手部、背景、延伸段接縫、音訊），依 [測試紀錄模板](templates/animation-test-record.md) 記錄；`content_review` 一律 pending，使用者明確決定後才用 `gameart.py review accept|reject` 記錄，failed 的結果不能 accept。不因瑕疵自動重送，每次 run 都是新資料夾。

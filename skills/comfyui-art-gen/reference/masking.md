# inpaint 遮罩細節

## 一般使用者優先用 Simple Mask Session

2026-09-05 已加入 repository 內建的極簡本機遮罩頁面。遮罩範圍必須經使用者確認；可由使用者在 `mask_session.py create` 產生的頁面塗紅，也可先採用 SAM 候選。手繪要查看 `preview.png`；SAM 要先看 contact sheet，再看選定候選的 preview。使用者按完成或已接受同一範圍，就沿用該確認；只有範圍改變或尚未確認時才詢問。手繪流程完成後以 `fetch` 取回三份檔案：`mask_editor.png`（黑白人類可讀）、`mask_comfy.png`（本產線 RGBA Alpha 契約）與 `preview.png`（原圖＋紅色半透明覆蓋）。

此工具的底層輸出仍遵守本頁既有規則：選取區 `alpha=0`，保留區 `alpha=255`。使用者介面刻意隱藏這個反直覺細節。空遮罩會拒絕儲存，選取超過 98% 會要求二次確認。它是獨立的純手動工具，不含也不依賴 SAM。自動分割應另做成獨立工具；兩者若要合作，只透過標準遮罩輸入／輸出選配串接。

`skills/comfyui-art-gen/SKILL.md` 的 `inpaint` 章節指向這裡——平常執行 `inpaint` 不用先讀這份,只有遇到「遮罩好像沒生效」「局部修圖結果變差/變爛」這類狀況時才查。

## 遮罩檔案格式(alpha 通道陷阱,已實測踩過一次)

`generate.py` 背後的 ComfyUI `LoadImage` 節點,`MASK` 輸出的邏輯是「**1.0 − 圖片的 alpha 通道**」,而且**圖片完全沒有 alpha 通道時,會直接回傳一個空白遮罩(等於什麼都不選、什麼都不會被重畫)**。也就是說:

- 要重畫的區域 = 那個像素的 **alpha 要是透明(0)**
- 要保留的區域 = alpha 要不透明(255)
- **不是**一般直覺以為的「存一張白色區域代表要重畫的灰階/RGB 圖」——如果遮罩圖沒有 alpha 通道(例如存成 RGB、或用 `.convert('RGB')` 處理過),不會報錯,但整個遮罩會靜默失效,產出看起來幾乎和原圖一樣,容易誤以為「有跑但沒什麼變化」而不是「根本沒吃到遮罩」
- 如果是 agent 自己用程式產生遮罩圖(不是透過 MaskEditor),**一定要存成帶 alpha 通道的 RGBA 圖片,要重畫的區域 alpha=0,其餘 alpha=255**,存完最好實際跑一次確認遮罩區域真的有變化,不要只看有沒有報錯就當作成功

## 不規則遮罩要先確認範圍再送測

遮罩形狀來自手繪、SAM 候選或程式轉換時，送測前要查看既有半透明預覽，沒有才合成；沿用使用者對相同範圍的確認，新增或改變範圍才重新確認；不要由 agent 盲猜座標直接跑正式生成。遮罩範圍抓錯(偏移、太大/太小、貼合到不該碰的區域)是純浪費一次生成的成本,而且錯誤形狀往往比原本沒修還慘(例如切到不該動的區域反而生出新的破綻)。

多邊形遮罩比矩形更能貼合不規則物體輪廓,但前提是使用者先確認形狀,沒確認的多邊形不會比矩形可靠。

## 遮罩範圍內同時要求「結構不能變、外觀要換」時,別用純 inpaint

如果要修改的區域裡有「關節/握姿/物體輪廓不能崩,但材質/造型要換成別的」這種衝突需求(換武器但握姿要對、換鱗片紋路但立體感要對),純 `inpaint` 沒有任何錨點鎖住結構,denoise 拉滿時結構跟外觀一起自由生成,失敗率會疊乘,不是加大遮罩或調羽化能解決的(2026-08-18 實測:女角色武器置換連續失敗多次,手指/武器造型反覆崩壞,直到改用 `guided_inpaint` 疊加 ControlNet 鎖住結構才穩定成功)。這種情況換用 `guided_inpaint`,不要留在 `inpaint` 裡死磕。

## 貼合度 / 羽化範圍 / denoise 要當成同一組參數

遮罩貼合度、羽化(柔化邊緣)範圍、`--denoise` 三者要一起判斷,不要只改其中一個。

遮罩越貼合物體真實輪廓(邊界越緊),就越需要「`--denoise` 拉滿(1.0,邊界內完全重新生成)」或「羽化範圍夠寬」兩者至少滿足一個;如果同時是「貼合度很緊 + 羽化範圍很窄 + denoise 沒拉滿」,模型會收到互相矛盾的訊號(一部分被要求保留原本結構、又被要求生出新內容但自由度不夠),常見結果是該區域變成沒有材質細節的死板色塊,而不是自然的修補效果。調整時先確認這三者的組合有沒有邏輯衝突,再判斷要調哪一個。

# inpaint 遮罩細節

`skills/comfyui-art-gen/SKILL.md` 的 `inpaint` 章節指向這裡——平常執行 `inpaint` 不用先讀這份,只有遇到「遮罩好像沒生效」「局部修圖結果變差/變爛」這類狀況時才查。

## 遮罩檔案格式(alpha 通道陷阱,已實測踩過一次)

`generate.py` 背後的 ComfyUI `LoadImage` 節點,`MASK` 輸出的邏輯是「**1.0 − 圖片的 alpha 通道**」,而且**圖片完全沒有 alpha 通道時,會直接回傳一個空白遮罩(等於什麼都不選、什麼都不會被重畫)**。也就是說:

- 要重畫的區域 = 那個像素的 **alpha 要是透明(0)**
- 要保留的區域 = alpha 要不透明(255)
- **不是**一般直覺以為的「存一張白色區域代表要重畫的灰階/RGB 圖」——如果遮罩圖沒有 alpha 通道(例如存成 RGB、或用 `.convert('RGB')` 處理過),不會報錯,但整個遮罩會靜默失效,產出看起來幾乎和原圖一樣,容易誤以為「有跑但沒什麼變化」而不是「根本沒吃到遮罩」
- 如果是 agent 自己用程式產生遮罩圖(不是透過 MaskEditor),**一定要存成帶 alpha 通道的 RGBA 圖片,要重畫的區域 alpha=0,其餘 alpha=255**,存完最好實際跑一次確認遮罩區域真的有變化,不要只看有沒有報錯就當作成功

## 不規則遮罩要先預覽再送測

遮罩形狀是 agent 自己畫的話(不規則區域、多邊形座標等),送測前先合成一張半透明預覽圖自己肉眼檢查形狀對不對,不要盲猜座標直接跑正式生成。遮罩範圍抓錯(偏移、太大/太小、貼合到不該碰的區域)是純浪費一次生成的成本,而且錯誤形狀往往比原本沒修還慘(例如切到不該動的區域反而生出新的破綻)。

多邊形遮罩比矩形更能貼合不規則物體輪廓,但前提是形狀要先驗證過,沒驗證的多邊形不會比矩形可靠。

## 貼合度 / 羽化範圍 / denoise 要當成同一組參數

遮罩貼合度、羽化(柔化邊緣)範圍、`--denoise` 三者要一起判斷,不要只改其中一個。

遮罩越貼合物體真實輪廓(邊界越緊),就越需要「`--denoise` 拉滿(1.0,邊界內完全重新生成)」或「羽化範圍夠寬」兩者至少滿足一個;如果同時是「貼合度很緊 + 羽化範圍很窄 + denoise 沒拉滿」,模型會收到互相矛盾的訊號(一部分被要求保留原本結構、又被要求生出新內容但自由度不夠),常見結果是該區域變成沒有材質細節的死板色塊,而不是自然的修補效果。調整時先確認這三者的組合有沒有邏輯衝突,再判斷要調哪一個。

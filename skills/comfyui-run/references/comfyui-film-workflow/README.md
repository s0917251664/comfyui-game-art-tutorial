# 劇情影片製作流程

本技能負責製作編排。生成能力由 [圖片技能](../comfyui-art-gen/README.md) 與 [影片技能](../comfyui-video-gen/README.md) 提供；不新增 graph、task、backend 或外部 provider。單角色遊戲動作組走 [角色動畫流程](../comfyui-character-animation-workflow/README.md)。

## 先界定交付與能力

沿用對話中已確定的故事、角色、參考圖、風格、比例、時長、聲音及使用者授權。缺少但不影響規劃的項目先寫明假設；只有影響成品的關鍵缺口才詢問。只要使用者要規劃，完成分鏡即可，不自動生成。

開始規劃生成路線前讀 `local_config.json`、`image_capabilities.json`、`video_capabilities.json`，依兩份生成技能處理缺失、過期及 unverified 狀態。缺生成能力仍可交付規劃，明列哪些鏡頭阻塞，不能把規劃當成可執行。

現有影片單鏡要求時長 2–6 秒、固定 24 FPS、生成長邊至多 768；實際時長依 backend 對齊影格。長影片是分鏡、逐支生成與剪接的製作流程，沒有一鍵長片或任意精確時長保證。劇情片若有台詞，先整理台詞並以本機 TTS 產生候選音檔、聽取後記下實測長度與停頓，再完成分鏡與時間預視，之後才逐鏡製作。工具和限制見[本機旁白與 Animatic](references/audio-tools.md)。需要嘴型同步時，可評估選配的[本機唇形同步 helper](references/lipsync-tools.md)；固定 helper 已通過技術契約 smoke，適用範圍限單一近正面臉部候選，嘴型自然度、騎士角色與劇情內容尚未驗收。字幕燒錄、ducking、time stretch 與複雜轉場仍需外部後製規格，不能宣稱已完成。

## 製作順序

1. **台詞與聲音時序（Dialogue timing）**：若有台詞，先整理台詞 ID、聲線、版本與停頓；用[本機旁白與 Animatic](references/audio-tools.md) 建立候選 TTS，聽取並記錄每句實測秒數。TTS 技術通過不代表台詞、表演或聲線已接受；修改台詞或聲音後更新版本與時間。
2. **劇情節拍（Story beats）**：用簡短段落寫事件的起因、動作、結果。每段說明觀眾應看懂什麼，再決定要幾個鏡頭。長作品按場景／段落分批，不一次產出全片。
3. **連續性紀錄（Continuity bible）**：固定角色身份參考、服裝／裝備、物件持有者、場景位置、光線與畫面左右方向；記錄事件前後改變。角色參考圖和 seed 是輔助，不保證身份或互動正確。
4. **粗分鏡（Storyboard）**：按 [鏡頭表模板](references/production-plan.md) 建表，依台詞候選的實測長度安排說話鏡頭與停頓。先用文字、簡單構圖或使用者草圖確定站位、景別、動作箭頭與剪接點；不要先精修全部畫面。文字表仍是文字分鏡，未畫圖不能稱為已完成視覺分鏡。需要繪製時按圖片技能檢查並生成構圖候選，或用已存在的畫圖工具；沒有可靠工具就交付待繪圖規格。
5. **節奏預視（Animatic）**：先核對鏡頭順序、台詞實測秒數、停頓與計畫時長加總；可用本機 helper 依靜幀及台詞音檔輸出有聲候選預視。沒有靜幀或音訊時標記未輸出預視影片，不把紙上檢查稱作 Animatic。
6. **代表鏡頭試作**：優先做最容易暴露角色身份、多人互動、物件持有者或接觸動作問題的一鏡。若已授權生成，按圖片技能完成起始靜幀候選，核對要求後讓使用者決定接受／調整；不能讓錯誤靜幀流入影片。既有接受素材可直接沿用，不重複問同一決定。
7. **逐鏡生成**：通過代表鏡頭後分批做其餘鏡頭。每鏡 prompt 只描述該鏡的主事件、起始狀態、動作與結束狀態；不把整篇劇本塞入一鏡。按下方路由轉交影片技能，保留來源與 sidecar。
8. **串接與驗收**：讀影片技能的 concat CLI，明確設定順序、尺寸和音訊政策。先核對相鄰鏡頭，再串接已接受版本；最終檢查全片是否看懂、節奏、實際時長與聲音。技術 pass 不代表內容接受（[R1](../../../../docs/knowledge/rules/candidate-review.md)）。

使用者若尚未接受必要素材，繼續完成不依賴它的規劃／整理，將依賴步驟標為待確認；不要把人工驗收擴大成每次生成前都重新索取授權。

## 鏡頭映射

| 鏡頭目的 | 既有 task／輸入 |
|---|---|
| 已定構圖中角色／環境動起來 | `img2video`：起始靜幀、該鏡動作 |
| 主要是推拉搖鏡、主體保持靜止 | `camera_move`：靜幀、支援的 camera 枚舉 |
| 參考角色演新鏡頭，首幀可改 | `character_video`：角色參考、該鏡描述 |
| 已有姿勢草圖，先做角色起始畫面 | 圖片 `character_action`：角色參考、姿勢圖；再驗收後走影片 |
| 有動作參考影片 | `pose_drive`：角色起姿圖、motion ref；依影片技能核對首幀 |
| 同場動作接續 | `clip_extend`：前片或尾幀；不是不同場景的普通切鏡 |
| A 狀態逐步變成 B | `transition`：起訖靜幀；不是硬切／疊化 |
| 依順序接片 | 本機 `video_concat`；不同場景通常各自生成後接片 |

各 task 是否可用依當次快照；本表不是 availability 清單。底層旗標與參數只由原技能／CLI 文件取得。

## 驗收與失敗處理

逐鏡先檢查主體、誰持有物件、動作方向、接觸位置、事件結果，再查角色、手部／裝備變形、背景和鏡頭。鄰鏡查左右方向、視線、持物手、衣裝損傷、光線、起訖狀態；故意跨軸或時間跳接要記明敘事理由。

多人接觸難可靠呈現時，可提出拆成「準備／接觸特寫／反應／結果」的分鏡候選；這是選擇性製作建議，不能偷偷改掉使用者要求的事件。模型把敵人的物件畫到主角手上屬內容失敗，不能靠 prompt 中有寫就判定成功。

失敗先分類為構圖、身份、動作／持物、時間連續性或技術契約問題。圖片修正次數沿用圖片技能；影片不自動重送。寫下可調原因與建議，沒有有效控制手段就標為受限。只重做受影響鏡頭；來源／起訖改變時標记其依賴鏡頭與舊合成待重驗，不讓新版本繼承舊版接受狀態。

## 交付與續作

在使用者指定位置或 repo `output/<production-id>/` 保存製作計畫、分鏡表、連續性紀錄與逐鏡版本路徑；不要覆寫已接受成品。狀態使用 `planned`、`blocked`、`candidate`、`accepted`、`rejected`；accepted/rejected 記錄使用者決定。技術狀態另記，不能混為一欄。對話已有決定可引用，不捏造。

回報已完成階段、成品／sidecar 路徑、待判斷鏡頭、未執行後製及下一個具體步驟。重新接手先讀製作計畫和已接受版本，不重做全片。不自動打開系統播放器。

## 參考來源與驗證狀態

研究來源及取捨見 [來源與本地化](references/sources.md)。流程由本專案重新撰寫；外部專案的安裝指令及 provider 不構成本機能力。此技能經文件與路由檢查，尚未完成端到端多鏡作品驗收；實際成果需逐鏡與整片驗證。

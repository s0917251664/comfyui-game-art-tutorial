# 物件、特效與角色動作的共用製作方法

本頁抽出可跨執行工具使用的工作順序與驗收問題。它不規定 CLI、模型參數、固定尺寸／FPS或執行器重試，也不是已驗證的 runtime。靜態圖片可依需求交給 ComfyUI 或有圖片工具的平台；短動態影片只有在當下確有相應影片工具時才可執行。本專案尚未整合平台影片執行。

## 物件系列與展示

只有製作新物件或系列變體時才走下面的代表素材／擴展步驟。已有母圖，只要展示、檢視或精確重複時，直接確認原檔、尺寸、Alpha 與組裝需求，再選可用的確定性工具；不為排版重新生成或編修物件。

1. **先做一件代表素材**：明確寫出系列共通身份／結構、可變欄位（例如顏色、材質、稀有度）及不得變動項。先生成或編修單件代表候選，驗收外形、比例、透明邊界、視覺風格和遊戲用途。
2. **確認系列規則後再擴展**：選定代表版本或明確規則後，再製作其他變體。逐件檢查差異是否只落在預期欄位、共同輪廓是否穩定；不要因同一批生成就推定系列一致。
3. **需要展示或檢視時選合成目的**：展示場景（scene）是將單件置於背景；檢視表（sheet）是並列候選／變體；圖樣重複（pattern）是重複同一母圖樣。這些是交付目的，不是通用 task 或執行方式。現有 ComfyUI Core helper 用確定性合成；平台若用生成模型重新構圖，會重畫內容，不能承諾原素材像素、數量或排列精確保留。需要精確組裝時，先確認有可用的確定性排版／合成工具，不能用生成式結果冒充同等操作。
4. **交付前**：保存代表素材及每個變體來源，說明檢視圖用途。檢查素材 Alpha、完整輪廓、留白、系列差異；展示合成圖不自動變成可交付透明素材，圖樣重複也不表示接縫無縫。

## 靜態與短動態特效

先區分要交付的是靜態特效素材、生成式短動態候選、綠幕影片、既有片段合成，還是來源影片遮罩／圖層處理。這些對應不同工具和輸入，不能只用「做特效」概括。

需求 brief 應說明：

- 特效外觀與用途（例如火焰、能量環、命中閃光），主體形狀、色彩、強弱、風格及不可出現項。
- 動態的起始／發展／結束狀態、速度與節奏；若要求循環，說清楚首尾如何銜接及哪些部分不能跳變。
- 背景要求（透明、純色、綠幕或場景）、前後景遮擋、鏡頭是否移動、特效相對主體的位置。
- 預期交付與用途，例如靜態圖、影片候選、合成預覽或供後續人工拆層；規格如解析度、FPS、時長、音訊、Alpha／色鍵等由實際接手工具確認，不在共用方法中預設固定值。

驗收至少看效果是否符合描述、運動是否穩定、主體是否漂移／變形、背景污染、邊緣／遮罩品質、首尾循環接縫及檔案規格。影片技術驗證只代表相應容器／編碼等檢查通過；不能代表 VFX 美術接受。除非已具備並驗證透明影片或圖集製作路線，不承諾影片候選能直接成為透明遊戲特效、Sprite Sheet 或已乾淨拆出的 VFX。

## 同一角色的動作集合

1. **建立角色母圖**：選定一張由美術明確確認的角色外觀來源，記下身份錨點（臉、髮型、服裝、配色、裝備、比例等）。要維持身份時，未接受候選不自動替代母圖。
2. **先選代表動作**：從需求動作表挑一支最能暴露身份、姿勢、道具或循環問題的代表動作。整理動作意圖、起姿／方向、場景、鏡頭、預期片長及保留身份項；每一項實際輸入需求由目標圖片／影片工具確認。
3. **代表候選逐項驗收**：分開檢查角色身份、動作是否可讀、姿勢與道具關係、鏡頭構圖、起訖狀態和 loop 接縫。技術檔案檢查與美術內容決定分開記錄。代表動作不合格時，先由使用者決定調整方向或停止，再擴展其他動作。
4. **擴展成動作表**：每列一個動作，記錄動作目標、輸入母圖／參考、保留項、交付形式、目前候選、接受狀態與備註。每支影片或圖片各自驗收；一支通過不代表整組身份、品質或技術狀態都通過。
5. **逐支選版與交付**：明確沿用已選定版本，保留其他候選供比較；由使用者決定 accepted／rejected。需要影格或後續合成時，使用所選執行工具明確支援且驗證過的後處理，不推定有通用透明拆幀或 Sprite Sheet 路線。

本方法只涵蓋遊戲角色圖片／短動態動作集合的規劃及驗收。劇情長片、旁白、混音與唇形同步屬其他專用流程，不由本頁擴大範圍。

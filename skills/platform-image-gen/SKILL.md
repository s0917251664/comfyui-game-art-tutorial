# 平台圖片生成與編修

只適用於本次平台會話實際提供的原生圖片生成或編修工具。不依賴 repo、ComfyUI、Python、模型檔或 `local_config.json`；不代表已接外部付費 API，不安裝客戶端、不讀 API key、不假定付費權限。

## 先檢查當下工具能力

需求與來源已完整時直接用既有 brief，只核對本案需要的欄位。看本次會話可呼叫的圖片工具與即時 schema，只用工具明確提供的欄位；不清楚就不編造工具、參數或模型。依需求逐項分成「明確支援」「不支援」「未知」：

- 文字生成、單張來源圖編修、多張參考圖（能否各自標明職責）、局部遮罩（格式與方向要求）、透明輸出、指定上一版為來源。
- 不可把單張圖支援推論成多參考、遮罩、Alpha 或版本功能。必要能力缺失或未知時，交付準備好的 brief 與具體缺口，不假裝已執行，也不因不相關的未知而阻止可完成的工作。

## 提交

1. 標清楚來源圖、角色、姿勢、外觀、背景、遮罩預覽各自的用途；工具不能獨立標註時，以它實際支援的形式提交，提示文字不會憑空創造多圖輸入。
2. 修改與保留項轉成工具接受的描述；不加 seed、denoise、ControlNet 等本機參數。要求範圍外逐像素保留時，語意編修不能承諾，需另有確認過的遮罩與確定性合成（見 [local-media-tools](../local-media-tools/SKILL.md)），沒有就回報此項阻塞。
3. 保留每個候選與其來源；只拿到圖或網址時，不宣稱已寫出本機檔案、取得 Alpha 原檔或建立 manifest。
4. 不盲目重送、不悄悄換工具、不覆蓋已回傳的候選；迭代時保留可追溯的輸入。

## 檢查與交付

工具回傳成功只表示有輸出。逐項對照需求：主體、指定修改、保留特徵、數量與空間關係、排除項、邊緣、格式與透明通道。只報實際看得到或檢查得到的；拿不到尺寸或 alpha 資訊就標為未核實。把觀察寫成具體差異（例如「外套顏色有改到，袖口輪廓也變了」）。新輸出預設是待確認候選，不替使用者 accept 或 reject（[R1](../../docs/knowledge/rules/candidate-review.md)）。brief 與驗收方法見 [brief 與驗收](../../docs/knowledge/art/brief-and-acceptance.md)。

## 範圍

只處理靜態圖片。影片、循環特效、逐幀遮罩、Sprite Sheet 都不在這裡；使用者提出影片需求時，整理成影片 brief 並說明此工具不處理。

# 平台圖片生成與編修

此技能只適用於本次平台會話實際提供的原生圖片生成或圖片編修工具。它可單獨提供給平台 Agent，並內含必要的 brief、版本及驗收規則；不依賴 repo、本機 ComfyUI、Python、模型檔、`local_config.json` 或其他專案路徑。它不代表已接入外部付費 API 或 CLI；不安裝第三方客戶端、不讀 API key，也不假定帳號有付費權限。先標明來源圖、角色／姿勢／外觀參考、遮罩預覽、修改與保留項，再核對平台實際支援什麼。

## 先檢查當下工具能力

需求與來源已完整時直接使用既有 brief，只核對本案需要的工具欄位後執行；不必先讀提示詞庫、完整職責盤點或重問引擎選擇。本技能接手圖片執行，共用需求與驗收方法以 `game-art-brief`（game-art-workflow reference）為準；下列素材欄位只用來核對提交輸入。

在執行前查看本次會話可呼叫的圖片工具與即時輸入 schema。只用工具明確提供的欄位及素材形式；工具名稱或說明不清楚時，不能自行編造 API、參數、模型、工具呼叫或付費權限。依需求分別確認：

| 能力 | 執行前需確認 |
|---|---|
| 文字生成 | 是否確有圖片生成工具、接受何種 prompt，以及它能回傳什麼產物 |
| 單張來源圖編修 | 是否能將指定圖片當作 edit target，以及可接受的格式／數量 |
| 多張參考圖 | 工具是否真的可同時接收多個獨立圖片輸入；各圖能否標明不同職責，或只可作一般參考 |
| 局部遮罩編修 | 是否有遮罩輸入；遮罩格式、黑白／Alpha 選區方向和尺寸要求是什麼。若 schema 沒有說清楚，標為未知並先不提交遮罩操作 |
| 透明輸出 | 是否能要求／回傳含 Alpha 的圖片；生成後仍須實際檢查 Alpha 通道與邊界 |
| 版本或沿用 | 是否能指定上一版為編修來源；工具若不支援則由 agent 保存並明確重傳輸入 |

只核對本案需要的項目，分清「明確支援」「不支援」與「未知」。不可把單張圖支援推論成多參考、mask、Alpha、編修或版本功能。必要能力缺失或未知時，仍可輸出準備好的 brief 及具體缺口；不要假裝已執行，也不因不相關能力未知而阻止可完成的工作。

## 整理並提交圖片工作

1. 先說清楚目標用途、要產生或修改什麼、畫幅／格式等交付條件，以及不可出現的內容。
2. 對每張圖片標註用途：來源／編修目標、角色身份、姿勢／結構、外觀／材質、背景、遮罩範圍預覽或候選。若工具不能獨立標註多張圖片，就以其實際支援的形式提交；提示文字描述角色不會憑空創造多圖輸入能力。
3. 將已整理的修改／保留需求轉成工具接受的描述。不得自行加入 ComfyUI 的 seed、denoise、ControlNet 或 mask 參數；只有當下工具明確支援的欄位才能提交。有控制欄位也不代表範圍外像素、角色身份或細節必然精確。若本案要求範圍外逐像素保留，單靠語意編修不能承諾；需另有已確認的遮罩、同尺寸對齊原檔及可執行的確定性合成／差異檢查，沒有時回報此項阻塞。
4. 只呼叫當下可用的圖片工具，傳入已核實格式的來源和必要欄位。若沒有圖片工具、本案必要能力檢查結果不明或工具拒絕必要輸入，停止相關執行並回傳 brief 與已知限制。沒有 mask／seed 不阻塞一般語意編修；不得因此承諾精確局部保留。
5. 保留每個回傳候選及其來源，版本採用依共用規則與使用者決定。只取得平台回傳圖或網址時，不宣稱已寫出本機檔案、取得 Alpha 原檔或建立本機 manifest；交付使用工具實際回傳的原生成品形式。

此技能不複製本機 ComfyUI 的重試次數或錯誤處理政策。依照當下平台工具允許的操作及使用者要求處理後續迭代；不得盲目重送、悄悄改換工具，或覆蓋已回傳候選。每次迭代應保留可追溯輸入，並讓使用者能比較候選。

## 檢查與交付

工具回傳成功只表示有輸出。逐項對照需求檢查主體、指定修改、必須保留的特徵、數量與空間關係、排除項、畫面邊緣和要求的格式／透明通道。只報告實際能看見或檔案檢查得到的結果；若工具不提供尺寸、alpha 或來源資訊，將該項標為未核實。

將觀察寫成具體差異，例如「外套顏色有改到，袖口輪廓也跟著變了」，不要只說「符合 prompt」。區分 Agent 的內容觀察與使用者的美術決定，預設新輸出為待確認候選；不替使用者標記接受或拒絕。回報工具路線、候選、已核實條件及剩餘限制。

## 能力範圍

本技能處理靜態圖片生成及圖片編修。它不執行影片、循環特效、影片合成、逐幀遮罩、VFX 抽取或 Sprite Sheet 製作。文字工具或靜態圖片工具不構成影片能力；使用者提出影片需求時，整理成影片 brief 並說明此工具不處理該工作。
